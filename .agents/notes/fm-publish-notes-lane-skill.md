Newly published skill scripts otherwise shipped with no shellcheck at all: a skill owns scripts at its own depth (`skills/<name>/test/run.sh`), so the match is recursive on purpose and anything published into `skills/` later is covered without another edit. Both the full-set path and the changed-mode predicate `fm_lint_is_canonical_root` were widened together, and `tests/fm-lint.test.sh` pins both. Consequence to keep in mind when publishing a skill: its scripts must also survive CI's stock macOS Bash 3.2 `-n` parse sweep, which iterates `bin/fm-lint.sh --list-files`.
- The published `skills/firstmate-notes/test/run.sh` differs from the source copy at `~/.claude/skills/firstmate-notes/test/run.sh` by exactly one line: a `# shellcheck disable=SC2016` comment added above the `contains()` helper. The suppression exists because the repo lints published skill scripts (previous note) while the source copy is linted by nothing; the source copy is deliberately left untouched.
- The published `skills/firstmate-notes/` is no longer a verbatim copy of the source at `~/.claude/skills/firstmate-notes/`, and "verbatim" should not be used to describe it. The divergence is exactly two things, and nothing else differs: (1) the one `# shellcheck disable=SC2016` comment line in `test/run.sh` described in the previous entry, and (2) a behavioral correction in `fm-notes.sh` to `scan`'s explicit-directory form - it now resolves each named directory through `resolve_dir` the way `path`/`new`/`list`/`count` already do, and reports a path it cannot read (exit `1`) instead of skipping it. Before, a typo'd path, a plain file, or a subdirectory instead of the worktree root all counted nothing and exited `0`, indistinguishable from a genuinely clear lane; `scan` now has three outcomes on three distinct exit codes - `3` pending, `0` clear, `1` could-not-look. The source copy is deliberately untouched and still carries the bug; closing that gap is firstmate's, not this task's.
- That `scan` bug predates this publish and was never reachable in practice while the skill had one user and one invocation (`FM_HOME`, whose targets are constructed rather than typed). It surfaced only because publishing forced `SKILL.md` to document the explicit-directory form for readers with no firstmate home, and review then checked whether the documented exit contract was true for that form. Publishing a grown local tool is what audits it: the contract it had always claimed was false for the audience it was about to acquire.
